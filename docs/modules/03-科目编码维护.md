# 科目编码维护功能需求说明

## 模块目标

科目编码维护用于在演示状态中调整科目编码，同时锁定科目名称、科目类型和财务口径，避免把“改编码”误操作成“改科目含义”。

## 当前功能范围

- 展示科目数量、已调整编码数量、正式科目数量、信用台账科目数量和生产控制覆盖数量。
- 展示原始科目编码、当前科目编码、科目名称、科目类型、对应主体、辅助核算维度、是否进正式分录、生产控制要求、编码状态、编码更新时间。
- 支持修改当前科目编码。
- 支持查看科目编码详情。
- 支持导出科目编码维护视图。

## 主要操作

- 点击“修改编码”打开抽屉。
- 抽屉中科目名称、科目类型、原始科目编码只读。
- 当前科目编码必须保存为 6 位数字，且不能与其他科目编码重复。
- 保存后同步更新凭证分录中同一锁定名称和已知编码对应的科目编码。

## 数据与口径

- 科目名称是锁定字段，不允许在此模块修改。
- 原始科目编码保留用于判断编码是否已调整。
- 修改后的编码会写入 `localStorage` 演示状态。
- 当前页面只演示编码维护；生产环境必须补启用日期、停用日期、版本号、审批记录和锁账后禁止修改规则。
- 联动凭证行后，需要重新计算凭证借方、贷方、信用台账金额和借贷平衡状态。
- 入账口径下，400101 手续费收入默认不启用；手续费默认走三方代扣/应付清算。
- v9 会计配置修正明确 `100201 三方支付应收-充值` 与 `100203 三方通道清算应收` 的阶段边界，避免同一阶段重复确认。
- `200102` 已调整为通用 `提现待付负债`，按会员、代理、站点提现通过辅助核算维度区分。
- `400101` 已调整为 `平台加收手续费收入（非默认）`，只有 fee_owner=platform 时才启用。
- v8 做账闭环补齐新增 `100301 预付金外部资产` 和 `100203 三方通道清算应收`，用于外部预付付款凭证和三方通道清算闭环。
- 新表中的资金模块字典要求官方账户、三方通道、提现待付、红包待领、预付外部资产、奖励成本、月结应收、场馆费应付、游戏收入成本和信用台账都有可追踪科目。
- 科目维护仍只处理原型编码，不代表真实会计科目主数据已同步到后端。

## 验收要点

- 非 6 位数字编码必须被拦截。
- 重复编码必须被拦截。
- 保存编码后，科目名称不变。
- 凭证批次、凭证详情分录、财务报表应使用最新科目编码。
- 详情中必须能看到辅助核算维度和生产控制要求，避免把前端演示编码误认为生产主数据已落地。
