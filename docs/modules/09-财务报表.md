# 财务报表功能需求说明

## 模块目标

财务报表用于将正式分录和信用台账分开汇总，避免把 fund_pool_balance 等信用类数据误放入资产负债表，同时让使用方能看到资产负债、收入成本和信用台账的当前演示口径。

## 细分说明

- 资产负债：汇总正式资产和负债科目，关注官方账户、三方清算、提现待付、红包待领和月结应收。
- 收入成本：汇总分润、月租、游戏净收入、奖励成本、场馆费和派奖成本等正式科目。
- 信用账户：单列 900xxx、fund_pool_balance、额度、钱包、冻结和控制类台账，不进入借贷平衡。
- 主体维度：按站点、发起主体、代理和会员维度展示，便于财务按业务归属复核。
- 报表导出：导出当前页签和筛选结果，口径跟页面一致。

## 当前功能范围

- 支持三个报表页签：资产负债、收入成本、信用台账。
- 更细的期间、主体、通道、待付待领、应收应付和业务域统计在“财务统计”模块查看。
- 资产负债页展示资产合计、负债合计、净额、信用类排除、官方账户、手续费清算、提现待付、红包待领、月结应收。
- 收入成本页展示收入、成本、利润口径、手续费收入、奖励成本、场馆/游戏成本。
- 信用台账页展示信用行数、台账增加、台账减少、净变动。
- 三个页签都按科目与信用台账汇总当前演示凭证；更细的缺口追踪和核销执行不作为报表前台模块。
- 报表明细和汇总展示站点ID/名称、发起主体身份、发起主体ID/名称，并尽量补充代理ID/名称、会员ID/名称，便于财务按主体链路核对。
- 支持导出当前报表页签数据。

## 主要操作

- 点击页签切换报表口径。
- 使用全局搜索或表内搜索筛选当前表格。
- 点击“导出报表”导出当前页签对应数据。

## 数据与口径

- 资产负债、收入成本只统计正式分录，排除 900xxx 和非正式行。
- 正式科目余额按借方发生额减贷方发生额计算。
- 信用台账统计 900xxx 与非正式行，展示台账增加、台账减少和净变动。
- 信用台账不使用正式借方/贷方命名，不参与借贷平衡。
- 手续费默认三方代扣/应付清算，不默认计入平台收入。
- 站点月结自动结算不等同现金收款，只有官方账户流水才代表真实现金。
- 新表中的 `资金模块字典` 决定哪些模块进入正式报表，哪些模块只进入信用台账或来源统计。
- 现金账户、三方清算、提现待付、红包待领、预付资产、奖励成本、月结现金、场馆费和游戏结算已在报表口径中分层展示。
- 三方通道清算、提现待付、红包待领、预付外部资产、奖励成本、场馆费、游戏投注/派奖等演示分录进入对应正式科目；内部额度、预付可用、费用快照只进信用台账或来源统计。
- 报表汇总基于演示凭证，不代表真实财务报表已由后端生成。
- 站点、代理、会员名称和ID为原型稳定演示归属；生产报表需要后端源单、凭证、账本和核销记录提供真实主体字段。
- 报表页负责科目余额汇总；财务统计页负责按业务资金模块和核销状态拆分统计。

## 验收要点

- 信用台账表头必须包含台账增加、台账减少、净变动。
- 会员充值成功的 900101/900102 应进入台账增加。
- 会员提现成功的 900101/900102 应进入台账减少。
- 导出信用台账时必须导出台账增减行，而不是正式科目余额。
- 资产负债表不得把 fund_pool_balance 计入现金资产。
- 从财务报表跳转口径上必须保持与财务统计一致：正式分录和信用台账分开汇总，手续费默认不计平台收入。
- 除总站类主体外，报表能展示的主体链路应尽量包含名称和ID，导出结果与页面字段保持一致。
